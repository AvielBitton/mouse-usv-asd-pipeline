# Neural-Network Baseline Runs — Sequence Models (Issue #60)

How the **sequence (neural-network) models** are trained on the official `--baseline`
dataset, and — the part worth reading carefully — **how their input data differs from the
tabular models**. This is the sequence-model counterpart of the tabular baseline runs
under [`results/tabular_models/`](../results/tabular_models/).

- Epic: [#42](https://github.com/AvielBitton/mouse-usv-asd-pipeline/issues/42) (training matrix) · This work: [#60](https://github.com/AvielBitton/mouse-usv-asd-pipeline/issues/60) · Reporting: [#52](https://github.com/AvielBitton/mouse-usv-asd-pipeline/issues/52)
- Pipeline: [`src/classification/neural_networks/sequence_pipeline.py`](../src/classification/neural_networks/sequence_pipeline.py) · mechanics in [`SEQUENCE_TRAINING.md`](../src/classification/neural_networks/SEQUENCE_TRAINING.md)

## 1. What this produces

Six runs — **3 architectures × 2 split modes** — all on the `--baseline` dataset:

| Model | `--model` | Dependent (default) | Independent (`--independent`) |
|-------|-----------|---------------------|-------------------------------|
| BiLSTM | `bilstm` | ✅ | ✅ |
| 1D-CNN | `cnn1d` | ✅ | ✅ |
| Transformer | `transformer` | ✅ | ✅ |

Each writes to `results/neural_networks/{model}_subject_eval_{dependent|independent}_baseline/`.
A roll-up lives in [`results/neural_networks/executive_summaries/sequence_models/`](../results/neural_networks/executive_summaries/sequence_models/) (`executive_summary.html` + `master_metrics.{csv,md}`), generated by [`scripts/generate_nn_executive_summary.py`](../scripts/generate_nn_executive_summary.py).

## 2. The key difference: tabular features vs. ordered sequences

Both pipelines start from the **same** upstream syllable table and apply the **same**
baseline filters. They diverge only in **how each training example is built**:

| | Tabular pipeline (XGBoost / TabPFN) | Sequence pipeline (BiLSTM / CNN1D / Transformer) |
|---|---|---|
| **One training row =** | one **recording**, aggregated | one **mouse-day-session**, kept as a sequence |
| **# examples (baseline)** | ~12,323 recordings | ~408 sessions (106 mice; 97 HT / 311 WT sessions) |
| **Feature shape** | flat vector, **48 columns** | sequence of **T × 14** (T = #syllables, padded/truncated to 256) |
| **Per-syllable info** | collapsed into per-type means/distributions | preserved, **in chronological order** |
| **Captures syllable order ("syntax")** | ❌ no — order is averaged away | ✅ yes — the model reads syllables in sequence |
| **Input file** | `tabular/all_data_external_baseline.csv` (numeric, headerless) | `sequence/all_data_external_baseline.xlsx` (syllable-level) |
| **Reads via** | `train_classifier.py --baseline` | `sequence_pipeline.py --baseline` |

### Tabular: aggregate, then flatten
The tabular pipeline groups syllables by recording and computes summary statistics
(per syllable-type average start/end frequency, type distribution, average duration), plus
metadata (mother genotype, sex, age, session, strain) — **48 numbers per recording**, one
row. All temporal structure within the recording is averaged away. See
[`src/classification/tabular/TRAINING.md`](../src/classification/tabular/TRAINING.md).

### Sequence: keep the order
The sequence pipeline does **not** aggregate. It groups syllables by `(Name, Day, Session)`,
sorts them chronologically (`Path` + `Syllable order (in recording)`), and feeds the model
the **ordered list of syllables**. Each syllable is a **14-dimensional** vector:

- **4 continuous** — Start Point (Hz), End Point (Hz), Duration, ISI time
- **8 embedding** — syllable type (0–10) → learned 8-dim embedding
- **2 binary** — Noise flag, Recording-boundary marker

Static per-session metadata (mother genotype, sex, day, session) is concatenated to the
sequence-encoder output before the final classifier. Variable-length sessions are
padded/truncated to `--max-seq-len` (default **256**; median session ≈ 236 syllables).
Full per-syllable mechanics: [`SEQUENCE_TRAINING.md`](../src/classification/neural_networks/SEQUENCE_TRAINING.md).

> **Why session-level, not recording-level?** A single recording has a median of only ~5
> syllables — too short to learn sequence patterns. Grouping into mouse-day-sessions yields
> a median of ~236 syllables per example.

## 3. Where the data lives (and why the directories are split)

Aggregation writes into two consumer-specific subdirectories under
`outputs/external/aggregated/`:

```
outputs/external/aggregated/
  tabular/    all_data_external_baseline.csv   ← 48-col aggregate (tabular pipeline)
  sequence/   all_data_external_baseline.xlsx  ← syllable-level    (sequence pipeline)
              all_data_external_baseline.seq_cache.csv  ← derived cache (gitignored)
```

This split exists because the two files used to share the base name
`all_data_external_baseline` in the same folder. The sequence pipeline caches its `.xlsx`
as a sibling `.csv` for speed — which **collided with the tabular `.csv`** and made
`--baseline` crash. Separating by consumer removes the collision permanently; the sequence
cache now uses a `.seq_cache.csv` suffix inside `sequence/`. Both are regenerated by
[`scripts/run_external_aggregation.py`](../scripts/run_external_aggregation.py). Paths and
row counts: [`BASELINE_DATA_MANIFEST.md`](BASELINE_DATA_MANIFEST.md).

## 4. How `--baseline` selects the data

`--baseline` overrides `--data-path` and points the pipeline at
`sequence/all_data_external_baseline.xlsx` — the syllable-level export with the official
baseline filters applied (`invalid_sex` + `supplement_offspring` removed on top of the
genotype binary filter; **`Noise == 1` syllables retained**). Filter definitions:
[`BASELINE_DATA_FILTERS.md`](BASELINE_DATA_FILTERS.md). All training-matrix runs must use
`--baseline` (Issue #46).

## 5. Split modes

| Mode | Flag | How it splits | Use |
|------|------|---------------|-----|
| **Dependent** (default) | — | random 60/20/20 at the **session** level; the same mouse can land in train and test | optimistic upper bound |
| **Independent** | `--independent` | 60/20/20 at the **mouse** level; all of a mouse's sessions stay in one set | honest generalization (no subject leakage) |

Mirrors the tabular `--independent` semantics. See [`CLI_Flags.md`](CLI_Flags.md).

## 6. Running the six configurations (CPU)

```bash
for m in bilstm cnn1d transformer; do
  .venv/bin/python src/classification/neural_networks/sequence_pipeline.py --model $m --baseline
  .venv/bin/python src/classification/neural_networks/sequence_pipeline.py --model $m --baseline --independent
done
# then regenerate the roll-up:
.venv/bin/python scripts/generate_nn_executive_summary.py --strict
```

Fixed seed (`SEED=100`) → reproducible. Training is CPU-only here (no GPU); BiLSTM is the
slowest (~10 min/run), the rest faster; early stopping (patience 15 on val AUC) usually
ends well before 100 epochs.

## 7. Reading the outputs

Per run:

| Path | Contents |
|------|----------|
| `results.json` | metrics: `test_accuracy`, `test_auc`, `train_accuracy`, `classification_report`, `epochs_trained`, `total_params`, … |
| `plots/` | `training_curves.png`, `confusion_matrix.png`, `confusion_matrix_counts.png`, `roc_curve.png` |
| `model/{model}_best.pt` | best checkpoint (by val AUC) + `scaler.pkl` |
| `logs/out.txt` | full training log (per-epoch metrics, classification report) |

**Class encoding — read this before interpreting metrics.** The current pipeline encodes
**`0 = WT`, `1 = HT`**. HT (heterozygous, the ASD model) is the **minority** class and the
clinically important one, so the metric to watch is **HT recall** =
`classification_report["1.0"]["recall"]`. High accuracy with low HT recall just means the
model predicts the majority WT class.

> ⚠️ **Legacy caveat:** the pre-baseline runs under `results/legacy/neural_networks/` used
> the **inverted** encoding (`HT (0)`). Do not compare their raw class indices directly.
> The summary generator detects HT by minority support and cross-checks the `HT (N)` index
> printed in `logs/out.txt`, so it is correct under either encoding.

## 9. Improving the results — imbalance, data & model settings

The initial baseline runs (§1) are poor: BiLSTM collapses to predicting **all-HT**
(acc 23%, WT recall 0%) and accuracy sits at/below the 76% majority baseline. A
data-engineer investigation found the cause is **not** a bug but the data + the
imbalance handling:

- **Weak intrinsic signal.** A tuned, class-balanced logistic regression on
  session-aggregated features ceilings at **ROC-AUC ≈ 0.63** (random split) and
  **≈ 0.50–0.57 by-mouse**. Genotype is barely separable across *unseen* mice with
  these acoustic features.
- **Operating-point collapse, not ranking.** The NN AUCs (0.60–0.79) sit *at or above*
  that simple-model ceiling — the catastrophic *accuracy* comes from
  `pos_weight = n_wt/n_ht ≈ 3.2` plus the fixed 0.5 threshold, which pushes the logit
  bias to all-HT.
- **Data scarcity.** 408 sessions, 97 HT, only **24 HT mice** (~14 in an
  independent-train); the test fold has only ~19 HT → single-split metrics are noisy.

**Levers (threshold tuning is a separate concern — Issue #29 — and excluded here):**

| Lever | Flags | What it targets |
|-------|-------|-----------------|
| Tunable class weighting | `--pos-weight-beta {1,0.5,0}` | the all-HT collapse (realigns the 0.5 operating point) |
| Class-balanced sampler | `--sampler balanced` (with `--pos-weight-beta 0`) | balanced minibatches → balanced base rate |
| Focal loss | `--loss focal` | confidence-based, gentler rebalancing |
| Regularization / smaller nets | `--weight-decay`, `--dropout`, `--hidden-size`, `--num-layers` | overfitting on the tiny independent-split data |
| Augmentation | `--augment-windows`, `--window-stride` | more (esp. HT) training examples from long sessions |
| Robust evaluation | `--cv-folds 5` | stable estimates given only ~19 test HT |
| Balanced metrics | (always reported) | `balanced_accuracy`, PR-AUC, MCC, macro-F1 — accuracy is misleading under imbalance |

**Experiment matrix** (run with `--baseline`, both splits, distinct `--results-dir`
under `results/neural_networks/experiments/`): `A` control · `B` β=0.5 · `C` β=0
· `D` balanced sampler · `E` focal · `F` regularized-small · `G` augmented · `H`
CV-verify the winner. Compare with:

```bash
.venv/bin/python scripts/generate_nn_executive_summary.py \
  --results-root results/neural_networks/experiments \
  --out-dir results/neural_networks/experiments/_summary
```

Rank `master_metrics.csv` by **`test_balanced_accuracy` / `test_mcc` / `test_average_precision`**,
not accuracy. **Honest expectation:** these levers fix the collapse and give honest
balanced numbers (large, certain win) plus modest AUC gains; subject-**independent**
generalization stays limited — a data ceiling, not a config bug.

### Findings (matrix run — best config per model × split, by balanced accuracy)

Full table: [`results/neural_networks/experiments/_summary/master_metrics.md`](../results/neural_networks/experiments/_summary/master_metrics.md).

| Model | Split | Best config | Bal Acc | vs control | HT rec / WT rec |
|-------|-------|-------------|--------:|-----------:|-----------------|
| BiLSTM | dependent | `--sampler balanced` (D) | 0.628 | **0.500 → 0.628** (collapse fixed) | 0.53 / 0.73 |
| BiLSTM | independent | `--sampler balanced` (D) | **0.704** | 0.655 → 0.704 | 1.00 / 0.41 |
| 1D-CNN | dependent | `--sampler balanced` (D) | 0.594 | 0.564 → 0.594 | 0.47 / 0.71 |
| 1D-CNN | independent | regularized-small (F) | 0.607 | 0.517 → 0.607 | 0.37 / 0.85 |
| Transformer | dependent | control (A) | 0.668 | (already best) | 0.68 / 0.65 |
| Transformer | independent | control (A) | 0.634 | (already best) | 0.79 / 0.48 |

**Takeaways:**
- The **balanced sampler** (`--sampler balanced --pos-weight-beta 0`) is the most reliable
  fix: it rescues the BiLSTM's all-HT collapse (dependent balAcc 0.500 → 0.628; WT recall
  0% → 73%) and gives the best overall result (BiLSTM independent, balAcc **0.704**).
- The **Transformer never collapses** — control is already its best; the rebalancing levers
  don't help it and can push it into the *opposite* (all-WT) collapse at the 0.5 threshold.
- A telling case for the (separate) threshold issue: `F_regsmall/transformer/independent`
  has the matrix's **highest AUC (0.815) and PR-AUC (0.62)** but balAcc 0.500 — strong
  ranking, wrong operating point. This motivates Issue #29 (out of scope here).
- Gains are real but bounded, consistent with the weak-signal ceiling; **independent**
  generalization remains modest.

### CV verification

The winning recipe (`--sampler balanced` BiLSTM) re-evaluated with 5-fold CV (grouped by
mouse for the independent split), under `results/neural_networks/experiments/H_cv_Dsampler__bilstm__*`:

| Split | Balanced accuracy (5-fold mean ± std) | AUC | Single-split was |
|-------|---------------------------------------|-----|------------------|
| dependent | **0.609 ± 0.055** | 0.673 ± 0.067 | 0.628 — **confirmed** (vs 0.500 collapse) |
| independent | **0.563 ± 0.063** | 0.689 ± 0.089 | 0.704 — **optimistic fold** |

**This is why CV matters.** The dependent fix is robust (0.61 ± 0.06, well above the 0.500
all-HT collapse). But the headline independent single-split **0.704 does not hold up** — with
only ~19 test HT it was a lucky fold; the honest 5-fold estimate is **0.563 ± 0.063**. Still
above chance and above the collapse, but it confirms that subject-**independent** generalization
is genuinely limited by the data, not recoverable by tuning. Report the CV numbers, not the
single best fold.
